## Method

- Every scenario ran against the live deployment (Cognee `1.6.10-local`, EBAC on) with the shipped plugin; no mocks.
- Each recall question ran in a **fresh `dsh headless` process** with a `--patch` overlay that isolates the project scope; wall-clock milliseconds include process start and model time.
- Adapter-level latency used the plugin's own `CogneeRestAdapter` (n=20 queries) and its write/ingestion gate, not a synthetic HTTP client.
- The no-memory baseline ran FIRST, before the codewords existed, with the plugin disabled (`enabled: false`) and every tool off; the same five questions were asked in one process and the planted codes counted.
- Scenarios that change deployment state (service restart, container restart) are named in their evidence and leave the deployment restored.
- A scenario is `BLOCKED` only when the environment cannot produce the condition; `SKIP` is an explicit deferral.
